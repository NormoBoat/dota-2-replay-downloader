# Dota 2 Replay Collector

Сервис на Go, который скачивает реплеи матчей Dota 2 по заданным `match_id` и хранит их в PostgreSQL вместе с метаданными и состоянием загрузки.

Матчи добавляются через HTTP API. Сервис получает координаты реплея из OpenDota, скачивает файл с CDN Valve, проверяет сжатие и заголовок, затем сохраняет файл в базе. Если OpenDota не дала координаты, предусмотрен запасной путь через Dota 2 Game Coordinator (GC) одного Steam-аккаунта. Очередь задач хранится в PostgreSQL; сетевые ошибки повторяются автоматически.

Проект рассчитан примерно на 100 матчей в день. Скачанные данные автоматически не удаляются. Реплеи занимают много места: при 100 матчах в день ориентируйтесь на несколько гигабайт прироста базы в сутки.

## Что уже работает

- CLI для настройки, входа в Steam, запуска и проверки состояния.
- HTTP API для добавления матчей, просмотра очереди и скачивания сохранённых реплеев.
- Загрузка через OpenDota и CDN: полный цикл проверен на реальном матче.
- Хранение реплеев, миграции и очередь в PostgreSQL.

Путь через Steam/GC реализован, но полный цикл на аккаунте владельца ещё не проверен. Проверка остановки под нагрузкой и суточный прогон на 100 матчах также остаются в плане. Веб-интерфейс запланирован; сейчас управление идёт через CLI и API.

Сервис не ищет матчи автоматически и не разбирает содержимое `.dem` для аналитики. Подробности и текущие задачи — в [plan/README.md](plan/README.md).

## Что нужно для запуска

- Go 1.27.2 или новее — версия указана в `go.mod`.
- Работающий PostgreSQL 16, отдельная база и пользователь с правами создавать в ней таблицы.
- Доступ к OpenDota и CDN Valve; для запасного пути — также к Steam/GC.
- Steam-аккаунт нужен только для GC. Без входа в Steam сервис работает через OpenDota.

Docker и Node.js для запуска не требуются. Ниже команды для PowerShell на Windows; на Linux соберите `collector` без `.exe` и запускайте как `./collector`.

## Быстрый запуск

### 1. Подготовьте базу

Подключитесь к PostgreSQL под администратором, например через `psql -U postgres`, и выполните:

```sql
CREATE USER collector WITH PASSWORD 'replace_with_your_password';
CREATE DATABASE dota OWNER collector;
```

### 2. Соберите программу и создайте настройки

Из корня проекта:

```powershell
go build -o collector.exe ./cmd/collector
.\collector.exe init -config settings.toml
```

`init` создаёт `settings.toml` со случайным ключом шифрования и API-токеном. Существующий файл не перезаписывается.

Откройте `settings.toml` и укажите подключение к своей базе:

```toml
[database]
dsn = "host=localhost port=5432 user=collector password=replace_with_your_password dbname=dota sslmode=disable"
max_open_conns = 20
```

Этот пример рассчитан на локальную базу. Для удалённого PostgreSQL используйте параметры TLS вашего сервера.

Остальные разделы оставьте созданными командой `init`. Справочный пример параметров — [settings.example.toml](settings.example.toml); напрямую копировать его для запуска нельзя, в нём стоят заглушки секретов.

Сохраните резервную копию `settings.toml`: в `[security] secret_key` находится ключ шифрования токена Steam. Не публикуйте этот файл и не меняйте ключ после входа в Steam.

### 3. Запустите сервис

```powershell
.\collector.exe run -config settings.toml
```

Сервис сам создаёт таблицы миграциями и работает до Ctrl+C. При недоступной базе повторяет подключение. Логи выводятся в stdout в формате JSON. Для одной базы допускается один работающий экземпляр.

В другом окне PowerShell проверьте состояние:

```powershell
.\collector.exe healthcheck -config settings.toml
.\collector.exe status -config settings.toml
```

По умолчанию API доступно по `http://127.0.0.1:8080`. Без `-config` программа ищет настройки рядом с исполняемым файлом.

## Добавление матчей и получение реплеев

Возьмите токен из раздела `[api] token` файла `settings.toml` и задайте его в текущем окне PowerShell:

```powershell
$headers = @{ Authorization = 'Bearer ВСТАВЬТЕ_ТОКЕН_ИЗ_SETTINGS' }
$baseUrl = 'http://127.0.0.1:8080/api/v1'

Invoke-RestMethod -Method Post -Uri "$baseUrl/matches" -Headers $headers `
    -ContentType 'application/json' -Body '{"match_ids":[9063023867]}'
```

Замените пример на ID недавно завершённого матча с доступным реплеем. Старый ID из примера подходит для демонстрации запроса, но его реплея уже может не быть на CDN. В один запрос можно передать до 500 ID; повторное добавление не создаёт дубликат матча.

Проверить результат:

```powershell
Invoke-RestMethod -Uri "$baseUrl/matches/9063023867" -Headers $headers
Invoke-RestMethod -Uri "$baseUrl/tasks?status=failed" -Headers $headers
```

Когда реплей сохранён, скачайте его:

```powershell
Invoke-WebRequest -Uri "$baseUrl/matches/9063023867/replay" -Headers $headers `
    -OutFile '9063023867.dem.bz2'
```

Файл отдаётся в исходном сжатом виде. Расширение `.dem.bz2` не гарантирует bzip2: поддерживается и zstd. Метаданные реплея содержат тип сжатия.

Все API-запросы, кроме `GET /api/v1/health`, требуют `Authorization: Bearer <token>`.

| Запрос | Назначение |
|--------|------------|
| `GET /api/v1/status` | Состояние сервиса, очередь, аккаунт и размер базы |
| `GET /api/v1/matches?has_replay=true` | Матчи с сохранёнными реплеями |
| `GET /api/v1/matches/{match_id}` | Матч, метаданные реплея и задачи |
| `GET /api/v1/tasks?status=failed` | Ошибки загрузки; причина в `last_error` |
| `POST /api/v1/tasks/{id}/retry` | Повтор задачи вручную |
| `GET /api/v1/account` | Steam-аккаунт, остаток лимита GC и диагностика |

Полный список маршрутов и параметров — в [plan/05-api.md](plan/05-api.md).

## Необязательный вход в Steam

Если нужен запасной источник координат реплея, при доступной базе выполните:

```powershell
.\collector.exe login -config settings.toml
```

Программа запросит логин, пароль и при необходимости код Steam Guard. Пароль при вводе не отображается и не сохраняется; токен входа хранится в базе зашифрованным.

По умолчанию приложение ограничивает запросы к GC сотней за окно 24 часа. Это настройка приложения, а не гарантия доступности со стороны Steam. Сессия открывается по необходимости и закрывается после двух минут простоя. Если Steam сообщает, что аккаунт уже играет, сервис откладывает GC-запросы. Детали поведения и ограничения — в [плане архитектуры](plan/01-architecture.md).

## Если загрузка не идёт

- База недоступна: проверьте PostgreSQL и `database.dsn`.
- API возвращает `401`: проверьте токен и заголовок `Authorization`.
- OpenDota не знает координаты, а Steam не настроен: выполните `login` для использования GC.
- Аккаунт в статусе `auth_failed`: повторите `login` вручную.
- Лимит GC исчерпан: время сброса видно в данных аккаунта.
- Реплей истёк или не был записан: повторная загрузка не восстановит отсутствующий файл на CDN.

Точная причина ошибки сохраняется в `last_error` задачи или аккаунта и выводится в логах.

## Состав проекта и план

- `cmd/collector/` — исполняемая программа и команды CLI.
- `internal/` — API, очередь, загрузчик, Steam-сессия, настройки и шифрование.
- `internal/store/migrations/` — SQL-миграции, включаемые в бинарник при сборке.
- `go.mod`, `go.sum` — зависимости Go.
- `settings.example.toml` — справочный файл настроек без секретов.
- [plan/README.md](plan/README.md) — архитектура, схема БД, API, задачи и план развёртывания.

Готовых Docker- и systemd-конфигураций в этой поставке нет; варианты развёртывания описаны в `plan/06-deploy.md`.
